# Data dictionary

All data is synthetic, generated by `src/generate_data.py` (seed 42). The raw files arrive as text, exactly as a real extract would, including the problems listed under each table.

## Raw extracts (`data/raw/`, loaded into the `raw` schema)

### customers.csv (36,543 rows)
| Column | Description |
|---|---|
| customer_id | Account id, `C000001` onwards; QA accounts start with `TEST` |
| email | Login email (all on example.com) |
| signup_date | Account creation date, `YYYY-MM-DD` |
| city | Home city, as typed by the customer |
| acquisition_channel | How the customer was acquired |
| device_type | Android, iOS, or Desktop |

Known problems: 540 duplicate accounts (same email typed with different case or spaces), 109 blank signup dates, city spellings like `KHI`, `lahore`, `Pindi`, and channel labels like `Facebook Ads` for Paid Social.

### sellers.csv (137 rows)
`seller_id`, `seller_name`, `seller_city`, `joined_date`, `seller_type` (Official Store or Marketplace Seller).

### products.csv (637 rows)
| Column | Description |
|---|---|
| product_id | `P00001` onwards |
| product_name, brand | Fictional brand plus product type |
| category, subcategory | 8 categories; category spelled 21 ways (case, "and" versus "&") |
| seller_id | Seller who lists the product |
| list_price, unit_cost | PKR |

### orders.csv (68,155 rows)
| Column | Description |
|---|---|
| order_id | `ORD0000001` onwards; QA orders start with `ORD9` |
| customer_id | Account that placed the order |
| order_datetime | Legacy system (before 2025-01-01): `DD/MM/YYYY HH:MI`. New system: `YYYY-MM-DD HH:MM:SS` |
| shipping_city | Delivery city, as typed; sometimes blank |
| payment_method | Legacy: `COD`, `Cash on Delivery`, `CC`, `WALLET`. New: `cash_on_delivery`, `card`, `jazzcash`, `easypaisa`, plus stray variants |
| promo_code | Blank, or `NONE` in the legacy system |
| courier | SwiftShip, PakRider, CityExpress, or RapidRoute (all fictional) |
| promised_delivery_date | Date promised at checkout, in the same format as the order's system |
| delivered_at | Delivery timestamp; blank if not delivered |
| order_status | Legacy: `DLVD`, `CNCL`, `RTO`. New: `delivered`, `cancelled` or `canceled`, `returned_to_origin`, `shipped` |
| shipping_fee | Legacy: text like `Rs. 150`. New: `150` |

Known problems: 272 exact duplicate rows, 45 QA test orders, 546 blank cities, 465 delivered orders with no delivery time, 58 delivery times earlier than the order.

### order_items.csv (106,765 rows)
`order_item_id`, `order_id`, `product_id`, `quantity`, `unit_price` (charged, after discount), `discount_pct`.
Known problems: 266 prices with an extra zero typed in (10x or 100x the list price), 106 zero or negative quantities.

### returns.csv (7,071 rows)
`return_id`, `order_item_id`, `order_id`, `return_reason`, `return_requested_date`, `refund_amount`.
Known problems: 14 orphan returns whose item does not exist.

### checkout_sessions.csv (98,799 rows)
One row per session that reached checkout during the A/B test, 2026-03-02 to 2026-04-26.
| Column | Description |
|---|---|
| session_id | `CS0000001` onwards |
| customer_id | Blank for guest checkouts |
| session_start | Timestamp |
| device_type, traffic_source | Device and where the visit came from |
| experiment_group | control or treatment, with variants like `Treatment ` and `TREATMENT` |
| session_duration_sec | Seconds on the checkout page |
| completed_order | 1 if the session ended in an order |
| order_value | PKR, when completed |

Known problems: 492 duplicate rows, 1,261 sessions under 3 seconds (scripted traffic).

## Cleaned tables (`clean` schema, built by `sql/02_clean.sql`)
| Table | Grain | Notes |
|---|---|---|
| city_map | one row per raw spelling | Lookup from lower-cased spelling to city, province, and tier |
| customer_id_map | one row per raw account | Maps every account to the canonical (earliest) account for its email |
| customers | one row per person | 36,000 rows after merging duplicates and removing QA accounts |
| sellers, products | one row each | Typed; categories standardised |
| orders | one row per order | 67,838 rows; timestamps parsed, labels mapped, cities standardised |
| order_items | one row per line | Prices corrected (flag `price_corrected`), bad quantities dropped |
| returns | one row per returned item | Orphans dropped |
| checkout_sessions | one row per session | Deduplicated; `is_bot` flags sessions under 3 seconds |

## Analysis tables (`mart` schema, built by `sql/03_model.sql`)
| Table | Grain | Key fields |
|---|---|---|
| fact_orders | one row per order (67,801) | gmv, net_revenue, delivery_days, is_late, is_rto, customer_order_seq |
| dim_customers | one row per customer (36,000) | cohort_month, acquired_in_mega_sale, first_order_late, repeat_within_90d, net_revenue |

37 orders drop out of `fact_orders` because their only item had an invalid quantity. The business questions are views on these tables, listed in `docs/project_brief.md`.
